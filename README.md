# 进销存数据库设计练习项目（SQL Server）

基于 SQL Server 的进销存（采购—销售—库存）数据库练习项目：从零设计表结构、约束与业务数据。

## 项目背景

计算机专业应届毕业生，求职方向为企业级软件（To B）领域：ERP 软件实施工程师/顾问、产品助理、技术支持。
国内中小型企业 ERP/进销存软件普遍以 SQL Server 作为底层数据库。本项目以上述就业场景为目标环境，从零设计一套进销存数据库，补齐三类岗位共通的「业务理解 + 数据库实操 + 文档输出」能力底座。

## 数据表说明

| 表名 | 用途 | 主要字段 |
|---|---|---|
| Goods | 商品资料 | 商品编码、名称、规格、单位、启用状态 |
| Supplier | 供应商资料 | 供应商编码、名称、联系人、电话 |
| Customer | 客户资料 | 客户编码、名称、联系人、电话 |
| Warehouse | 仓库资料 | 仓库编码、名称、位置、启用状态 |

四张表均设置自增主键与编码唯一约束。当前阶段仅保存基础资料，尚未建立出入库业务关联；Warehouse 仅保存仓库档案，暂不记录商品库存数量（库存计划以“余额表 + 流水表”方式在后续阶段实现）。

## 核心设计说明

1. **主键与业务编码分离**：GoodsId 等自增主键用于数据库内部关联，GoodsCode 等业务编码面向用户且唯一。这是 ERP 系统的常见设计。
2. **金额与数量使用 DECIMAL(18,2)**：避免 FLOAT 的浮点精度误差；数量允许小数，以支持按重量、长度计量的商品。
3. **中文字段统一使用 NVARCHAR 并在插入时加 N 前缀**：保证中文正确存储与排序。
4. **统一审计字段**：各表 CreateTime 默认 SYSDATETIME()，自动记录数据创建时间。

## 使用方法

### 环境准备

准备可连接的 SQL Server 实例，使用具备建库、建表及插入数据权限的账号连接 SSMS。
脚本使用 T-SQL 与 GO 批处理分隔符，需在 SSMS 等支持该语法的工具中执行。

### 执行顺序

在测试环境中依次执行：

1. `01_create_database.sql`：创建数据库 Inventory
2. `02_create_tables.sql`：创建基础资料表
3. `03_sample_data.sql`：插入示例数据

> ⚠️ `01_create_database.sql` 会强制断开已有 Inventory 数据库的连接，删除该库并重新创建，原有数据会全部丢失。该逻辑仅用于本地练习环境，切勿用于生产库。

> 说明：01 是“重置入口”，完整流程 01→02→03 可反复执行；单独重复执行 02/03 会因对象已存在而报错，重跑 01 即可恢复干净环境。

### 验证

完整执行后，运行以下只读查询：

```sql
USE Inventory;
GO
SELECT N'商品'   AS DataType, COUNT(*) AS RecordCount FROM dbo.Goods
UNION ALL
SELECT N'供应商', COUNT(*) FROM dbo.Supplier
UNION ALL
SELECT N'客户',   COUNT(*) FROM dbo.Customer
UNION ALL
SELECT N'仓库',   COUNT(*) FROM dbo.Warehouse;
```

预期记录数分别为 30、30、30、10。
