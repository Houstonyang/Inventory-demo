# 进销存数据库设计个人项目（SQL Server）
基于 SQL Server 的进销存（采购—销售—库存）数据库项目：从表结构、约束和业务数据入手，逐步练习业务建模与 SQL 查询。
当前已完成 **8 张表、基础档案与采购业务示例数据、3 个业务查询**，可以演示采购订单、实际收货及待收数量的关联分析。全部脚本已按 01→02→03→04 从空库完整执行验证通过；销售与库存管理仍在规划中，当前尚未形成完整的进销存系统。
## 项目背景
计算机专业应届毕业生，求职方向为企业级软件（To B）领域：ERP 软件实施工程师/顾问、产品助理、技术支持。国内中小型企业 ERP/进销存软件普遍以 SQL Server 作为底层数据库，本项目以此为目标环境，练习三类岗位共通的：
- **业务理解**：区分基础档案、订单、入库单，以及订购数量与实收数量；
- **数据库实操**：设计主外键、业务编码、单据表头与明细，编写连接和聚合查询；
- **文档输出**：记录数据关系、运行步骤、样例结果及当前限制。

## 数据表与业务关系
| 表名 | 用途 | 主要字段或关联 |
| --- | --- | --- |
| Goods | 商品档案 | GoodsCode、GoodsName、GoodSize、Unit、IsActive |
| Supplier | 供应商档案 | SupplierCode、SupplierName、Contact、Phone |
| Customer | 客户档案 | CustomerCode、CustomerName、Contact、Phone |
| Warehouse | 仓库档案 | WarehouseCode、WarehouseName、Location、IsActive |
| PurchaseOrder | 采购订单表头 | OrderNo、SupplierId、OrderDate、Status |
| PurchaseOrderDetail | 采购订单明细 | OrderId、GoodsId、Quantity、Price、Amount |
| PurchaseIn | 采购入库单表头 | InNo、SupplierId、WarehouseId、OrderId、InDate、Status |
| PurchaseInDetail | 采购入库单明细 | PurchaseInId、GoodsId、Quantity、Price、Amount |
一张采购订单包含多条商品明细；结构上支持一张订单关联多张入库单（用于分批收货），当前样例中每张订单对应一张入库单，尚未演示分批收货。一张入库单对应一个供应商和一个仓库，并包含多条实收商品明细。
PurchaseIn.OrderId 允许为空，结构上支持无来源订单的入库；当前示例中的三张入库单均关联订单。Warehouse 只保存仓库档案，入库记录尚不会自动生成库存余额或库存流水。
## 核心设计说明
1. **主键与业务编码分离**：八张表均使用自增主键；基础档案编码、采购订单号和入库单号具有唯一约束。
2. **表头与明细分离**：表头保存供应商、日期等整单信息，明细保存商品、数量、单价和金额，通过外键关联表头，避免单级信息在每行商品中重复存储。
3. **数量与金额使用 DECIMAL(18,2)**：支持两位小数；示例数据中 Amount = Quantity × Price，该一致性当前由数据录入过程保证。
4. **使用 Unicode 文本**：文本字段使用 NVARCHAR，中文示例字符串使用 N 前缀；数据库排序规则为 Chinese_PRC_CI_AS。
5. **创建时间自动记录**：各表 CreateTime 默认使用 SYSDATETIME()。
6. **状态字段标识单据阶段**：单据状态默认 DRAFT，采购订单示例包含 DRAFT、APPROVED、CLOSED，用于标识单据所处阶段。
7. **外键约束保障引用完整性**：全部外键按 FK_本表_被引用表 命名；除校验引用对象存在外，也会阻止删除已被引用的数据（详见测试记录）。
## 示例业务场景
| 场景 | 示例订单 | 数据表现 |
| --- | --- | --- |
| 全部到货 | PO20260910001、PO20260912001 | U盘订购/实收 100/100，订书机 200/200；订单状态为 CLOSED |
| 部分到货 | PO20260915001 | 精密轴承订购 500、实收 300、待收 200 |
| 尚未收货 | PO20260918001、PO20260922001、PO20260923001 | 已有订单明细，尚无关联入库单 |
| 草稿订单 | PO20260920001、PO20260921001 | 仅有订单表头，尚无明细和入库单 |
这些状态由示例数据直接指定，不代表系统已经实现自动审核或自动关闭订单。
## 业务查询与预期结果
04_queries.sql 包含三个只读查询，可在数据准备完成后重复执行；每条查询的预期结果已注释在脚本中。
| 查询 | 业务用途 | SQL 要点 | 当前样例预期 |
| --- | --- | --- | --- |
| 采购明细清单 | 查看每张订单的供应商、商品、数量、单价和金额 | 四表 INNER JOIN | 9 行 |
| 供应商采购金额汇总 | 按采购金额比较供应商，并统计订单数 | GROUP BY、SUM、COUNT(DISTINCT) | 4 行 |
| 收货跟踪表 | 对比订购、实收和待收数量 | LEFT JOIN、SUM、ISNULL | 9 行；精密轴承为 500 / 300 / 200 |
供应商汇总预期按金额降序显示：
| 供应商编码（便于核对） | 订单数 | 采购总金额 |
| --- | ---: | ---: |
| S001 | 2 | 19950.00 |
| S003 | 1 | 12500.00 |
| S002 | 2 | 8300.00 |
| S004 | 1 | 6540.00 |
该查询实际显示供应商名称；金额来自订单明细，不是实际入库金额或付款金额。三个查询均从订单明细出发，因此不包含没有明细的两张草稿订单。
当前查询口径与边界：
- 供应商汇总按名称分组；若未来出现同名供应商会被合并统计，届时应改为按供应商 ID 分组。
- 收货跟踪按来源订单和商品匹配实收数量，尚未筛选入库单状态；未来出现草稿入库单时，需要明确哪些状态计入实收。
- 当前样例中同一订单的同一商品只出现一条明细，数据库尚未限制这一点；若允许重复商品行，需要完善明细关联与汇总逻辑，避免实收数量重复计入。
## 使用方法
### 环境准备
准备可连接的 SQL Server 实例，并使用具备相应建库、建表、插入和查询权限的账号连接 SSMS。脚本使用 T-SQL 和 GO 批处理分隔符，应通过支持该语法的工具运行。
### 首次初始化
**01_create_database.sql 会强制断开已有 Inventory 数据库的连接，删除整个数据库并重新创建，原有数据会全部丢失。仅在确认可以清空的本地练习环境使用。**
确认目标实例和数据后，依次执行：
1. `01_create_database.sql`：创建空的 Inventory 数据库。
2. `02_create_tables.sql`：创建基础档案和采购业务表。
3. `03_sample_data.sql`：插入示例数据，查看末尾的记录数统计。
4. `04_queries.sql`：查看三个业务查询的结果。
示例业务数据直接使用 1、2、3 等主键 ID，因此依赖全新建表后的自增编号和脚本中的插入顺序，不适合直接追加到已有业务数据的数据库。
### 重复执行与日常练习
- 已完成初始化时，直接运行 `04_queries.sql` 即可练习查询。
- `02_create_tables.sql` 尚未加入存在性判断，重复执行会遇到“对象已存在”错误；修改已有表应使用经过确认的 ALTER TABLE 脚本。
- `03_sample_data.sql` 尚未加入防重复逻辑，重复执行可能触发编码或单号唯一约束错误，也可能重复插入明细；脚本未覆盖全过程事务，不能假定一次报错会回滚全部操作。
- 只有确实需要清空并重建测试数据时，才重新执行 01 → 02 → 03；不要将删库重建当作日常消除报错的方法。

## 当前限制与下一步
- **业务规则**：尚未校验数量必须为正、价格不能为负、金额与数量单价一致，也未限制状态取值。
- **采购一致性**：外键保证引用对象存在，但尚未保证入库供应商与来源订单一致、入库商品属于来源订单，或实收数量不超过订购数量。
- **库存与销售**：已具备采购订单和入库记录的表结构及样例，尚未实现库存过账、余额、流水、销售出库及负库存校验。
- **应用层**：尚无业务接口、操作界面和权限管理流程。
- **简化说明**：入库单价按订单价录入；实际业务中按发票价，可能与订单价不同。
- 下一阶段优先完善采购数据校验和收货查询，再扩展销售与库存表，并通过存储过程与事务逐步实现单据处理和库存更新。
